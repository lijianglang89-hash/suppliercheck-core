## 4. 技术架构

| 层 | 选型 |
| --- | --- |
| Frontend | Next.js 16.3.6（App Router）+ TypeScript 5 + Tailwind CSS v4 |
| Backend | Next.js Server Components / Route Handlers / Server Actions（不额外起 Node API） |
| Database | PostgreSQL 16（标准协议，不绑定托管供应商） |
| ORM | **Drizzle ORM 0.45.3 + drizzle-kit 0.31.11** |
| Validation | Zod 4 |
| Storage | `StorageProvider` 抽象 + `LocalStorageProvider`（私有卷 + HMAC 签名 URL） |
| AI Provider | `AIProvider` 抽象 + `MockAIProvider`（显式标注开发模拟） |
| Deployment | Docker Compose（app + postgres）+ 宿主 nginx 反代（模板待启用） |

### ORM 选型理由：为什么是 Drizzle 而不是 Prisma

1. **运行时开销** —— Drizzle 是纯 TypeScript，编译后就是 SQL；Prisma 附带查询引擎二进制，
   在只有 4 GB 内存且与 9 个容器共存的机器上，这部分开销不划算。
2. **迁移产物可审阅** —— drizzle-kit 生成的是**纯 SQL 文件**（本项目为
   `db/migrations/0000_lazy_captain_flint.sql`），可以直接读、直接改、直接拿去任何 PostgreSQL 执行。
   这既方便人工审计，也让**未来的 AI Agent 能读懂改懂数据层**——这是本产品的长期诉求。
3. **类型安全** —— 从 schema 直接推导 TS 类型，不需要 `prisma generate` 这一步，CI 少一环。
4. **可迁移性** —— 迁移产物就是标准 PostgreSQL DDL，将来迁到阿里云 RDS / Supabase 零改动。

### AI Provider 抽象（需求第五、六条）

接口位于 `lib/ai/types.ts`，已预留 5 个能力：

`generateText()` · `generateStructuredOutput()` · `classify()` · `extractEntities()` · `analyzeEvidence()`

- 业务代码只调用 `getAIProvider()`，**不出现任何厂商 SDK 或硬编码模型名**。
- 每个返回值都带 `mock: boolean`，UI 据此显示"开发模拟"标记。
- 未来接入 OpenAI-compatible 服务（百炼 / Qwen / OpenAI / DeepSeek / Kimi）时，
  只需在 `lib/ai/index.ts` 的 `PROVIDER_FACTORIES` 注册一个工厂，调用方零改动。
- **Mock 的行为是诚实的**：无法产出结构化结果时**直接抛错**，绝不编造；
  `classify()` 恒返回 `Other` 且置信度为 0；`extractEntities()` 返回空数组。
- V0.1 不需要任何 API Key 即可完整运行。

## 6. 安全

### 已实现

| # | 措施 | 落点 |
| --- | --- | --- |
| 1 | MIME type 白名单 | `lib/files.ts` `ALLOWED_MIME_TYPES` |
| 2 | 文件大小限制 | `MAX_UPLOAD_BYTES`（默认 25 MB），`validateUpload()` |
| 3 | 文件名清洗 | `sanitizeFilename()`：剥路径、去控制字符、干 `..`、处理 Windows 保留名、截断超长 |
| 4 | 路径穿越防护 | `assertSafeStorageKey()` + `path.resolve` 前缀复核，双保险 |
| 5 | UUID 文件名 | `buildStorageKey()` → `workspaces/<uuid>/documents/<uuid><ext>` |
| 6 | 不信任扩展名 | 扩展名由 MIME 白名单**反查**得出，忽略用户提供的 |
| 7 | 不信任内容类型 | **魔数嗅探** `sniffFileSignature()`，声明与真实字节不符即拒绝 |
| 8 | 不允许执行 | 私有目录 + 无任何静态映射；上传物不在 `public/` |
| 9 | 私有 storage | `LocalStorageProvider` 根目录来自 `STORAGE_PATH`，权限 0640/0750 |
| 10 | 删除能力 | `delete()` 幂等；文档走软删除 `deleted_at` |
| 11 | 上传审计 | `documents` 表记录 checksum / 原始名 / 安全名 / 创建人，`document_processing_jobs` 记录任务 |
| 12 | 失败状态 | 文档状态机含 `FAILED`；任务状态机含 `FAILED` + `error_code` / `error_message` |
| 13 | 日志不写文件内容 | `lib/logger.ts` `redact()`：敏感键整值替换、长串截断、二进制只记长度 |
| 14 | 多租户授权 | `checkWorkspaceMembership()` 把 (用户, 工作区) 回库核对，**浏览器传的 workspace_id 不作为依据** |
| 15 | 授权失败不泄露存在性 | 「工作区不存在」与「无权访问」返回同一文案 |
| 16 | 密码哈希 | scrypt（N=16384/r=8/p=1），随机盐，`timingSafeEqual` 比较 |
| 17 | 会话 Cookie | HttpOnly + SameSite=Lax + 生产环境 Secure，HMAC-SHA256 签名，7 天有效期 |
| 18 | 防 open redirect | `resolveSafeRedirect()` 拦截绝对 URL、协议相对 URL、控制字符 |
| 19 | 防账号枚举 | 登录失败不区分「邮箱不存在」与「密码错误」，且等开销校验 |
| 20 | 统一错误模型 | `lib/errors.ts`：401/403 严格区分，用户只看到安全文案，诊断信息进日志 |
| 21 | 环境变量校验 | Zod，缺关键项**拒绝启动**；空字符串视作未设置 |
| 22 | 健康检查不泄露 | `/api/health` 只返回 status / database，不返回 DSN、路径、环境变量 |
| 23 | 安全响应头 | `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy` |
| 24 | Server Action 鉴权 | 每个 action 内部独立鉴权，不依赖渲染层 |

## 12. 已知问题

如实列出，不粉饰。

1. **本地 Docker Desktop 无法启动**（进程启动后未驻留），因此本地没有独立数据库，
   开发与测试通过 SSH 隧道连服务器上的 PostgreSQL。若需要本地独立库，需手动启动 Docker Desktop
   后执行 `docker compose up -d postgres`。

2. **`APP_URL` 在构建期固化**。首页、sitemap.xml、robots.txt 是静态预渲染，
   它们的 canonical / og:url / 绝对 URL 在**构建时**确定。
   ⇒ **换正式域名后必须重新构建镜像**（`docker compose up -d --build app`），改环境变量重启无效。
   这是静态渲染换来的性能优势对应的代价，已记录在 Dockerfile 注释里。

3. **尚无正式域名**。当前 `APP_URL=http://127.0.0.1:3010`，仅本机可达，
   **公网目前无法访问**。Nginx 反向代理只提供了模板
