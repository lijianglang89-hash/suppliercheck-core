# 供应商智审 · 设计系统

> 任何修改 UI 的 Agent 先读本文件。改完要确认没有违反这里的硬规则。
> 本文件是**约束**，不是灵感板。

---

## 0. 三条硬规则（违反即打回）

1. **不把确定性规则包装成 AI。**
   审核结论由 15 条规则产出，不是模型判断。文案里不出现「AI 审核」「人工智能审核」，
   SEO keywords 里也不出现。可以说「自动核对」「智能解析」，但**主语不能是 AI**。
   曾经首页写着「AI 审核能力开发中」，SEO 里写着「AI 文档审核」，两条都已清除。

2. **页面上的数字必须来自真实功能。**
   可以写「15 条审核规则」「5 类检查」，因为那是 `RULE_IDS` 和 `FINDING_CATEGORIES` 的真实数量。
   不可以写「准确率 99.9%」「节省 87% 时间」——没有测量就没有数字。

3. **所有产品示意必须标「示例数据」。**
   Mockup 里的公司名、发现条数都是造的。不标就是伪造证据。

| 用途 | 用哪个 |

| Logo / 导航 / 视觉主文字 | **供应商智审** |
| SEO title / meta / 正式产品描述 / 页脚 | **供应商资料智能审核系统** |

`lib/site.ts` 里三个名字成对定义（`name` / `shortName` / `latinName`），
**不要再造第四个名字**。

## 2. 颜色

保留现有系统，不换主题：

```
brand-600   #2f6097   主色（沉稳蓝，不是亮蓝）
brand-700   #274e7b   主按钮
ink-900     #161a21   一级标题
ink-600     #4d5563   正文
ink-50      #f7f8f9   页面背景（不是纯白）
white       #ffffff   卡片
ink-200     #e2e5e9   边框

brand-tint  #edf4fa   产品展示区底色
brand-mist  #f2f6f9   文件卡 / 流程节点底

success-600 #1f7a4d   通过
warning-600 #a35a06   待确认
danger-600  #b3261e   问题
```

**禁止**：紫色渐变、霓虹、发光、玻璃拟态、大面积渐变、夸张阴影。

### 状态色的语义（全站唯一）

| 状态 | 颜色 | 含义 |
|---|---|---|
| 通过 | 绿 | 命中规则且无异常 |
| 待确认 | 橙 | 需要人工核实（含"无法判定"） |
| 问题 | 红 | 已确认异常 |

⚠️ 系统内部的 severity 是 `INFO < LOW < MEDIUM < HIGH < CRITICAL`，
**与展示层的三态不是一对一**。映射只做一次，写在 `lib/reviews/labels.ts`，
页面不各自发明映射。

## 3. 排版与节奏

- **禁止整页白底白卡片**。区块底色要在 白 / 浅灰 / 浅蓝 / 深蓝 之间交替。
- **禁止六个一样的卡片排一排**。每个卡片要么带数据、要么带小型 UI、要么带状态。
- 卡片圆角 8px（`--radius-card`），按钮 8px。不用 24px+ 大圆角。
- 字号层级：H1 `text-4xl/5xl`、H2 `text-2xl`、H3 `text-base`、正文 `text-sm/base`。

---

## 4. 视觉素材

**不用**：商务人士照片、握手照、工厂航拍、Shutterstock 素材。

**用**：文件卡 → 审核 → 结果 这条链，全部用 HTML/CSS/SVG 现做。
原因：产品本身最好的视觉就是它自己的界面；而且这条链可以复用到
首页、产品页、社媒、宣传视频。

图标：**不引入图标库**（Lucide 之类的依赖不值得）。用 inline SVG，
风格统一为 1.5px 描边、无填充。

**禁止**用 🚀 ✨ 🤖 🔥 这类 emoji 当 UI 装饰。

---

## 5. 动画

只允许微交互：hover、fade、slide、progress。
**禁止**：粒子、发光、连续动画、自动轮播。

---

## 6. 导航

导航项必须指向**真实存在的页面或锚点**。
曾经有建议加「产品 / 功能 / 使用场景 / 价格 / 帮助」——
这些页面都不存在，加了就是死链。当前导航只指向登录、注册与首页锚点。
「价格」在定价公布前不出现。

---

## 7. 响应式

检查断点：1440 / 1366 / 1024 / 768 / 430 / 390 / 375。

- 不产生横向滚动
- Hero 在 768 以下改单列，产品视觉放到文字下方
- 表格外层要能横向滚动
- 流程区在移动端改纵向时间线

---

## 8. SEO / GEO 不能被视觉重构破坏

- 营销文字必须留在 HTML 里，**不能全变成图片**
- 保持 title / description / canonical / robots / sitemap
- 保持 heading 层级（一个 H1，H2 分节）
- 公开页面仍要说明：这是什么、解决什么问题、适合谁、有哪些功能、怎么工作、**有哪些限制**

---

## 9. 无障碍

对比度达标、focus visible、按钮有明确文字、表单有 label、
键盘可导航、图片有 alt、heading 层级正确。

---

## 10. 改版验收流程

1. 改之前保存首页截图（1440 + 390）作为 baseline
2. 改之后同样两个断点再截
3. 逐项比：布局 / 颜色 / 字体 / 间距 / 层级 / CTA / 移动端
4. **如果更差就回滚**，不要因为已经写了就保留
